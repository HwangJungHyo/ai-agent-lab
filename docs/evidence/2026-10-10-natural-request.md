# 자연어 제안을 검증하고 실행 여부를 통제하는가?

- 기록일: 2026-10-10, Asia/Seoul.
- 상태: 사용자 PC에서 명확한 요청의 표현 정규화·조회 조건 미리보기와 모호한 요청의 대상·시간·증상 질문을 확인했다. 두 미리보기 사례와 자연어 입구의 실제 Loki 조회·코드 사실 출력을 확인했다. 실제 설명에 limit 관련 근거 없는 가능성이 남아 의미 정확성은 별도 보완 대상이다.
- 기준 작성 시점: 작업 시작 commentary에서 모호한 요청의 추가 질문, 미리보기 기본, 명시적 실행 정책을 제시했다. 아래 상세 표는 검증 후 정리다.

## 결정할 질문과 기존 근거

사용자가 CLI 대신 자연어로 요청할 때, 명확한 조건만 실제 조회에 전달하고 모호한 조건은 질문으로 돌려보낼 수 있는가?
기존 [Loki 그래프 연결](2026-10-10-loki-graph.md)의 실제 사용자 PC 로그를 수집 경로의 근거로 재사용한다. 새로 바뀐 것은 의미 해석 입구, 입력 계약, 실행 분기다. Loki 서버 자체의 장애 주입은 반복하지 않는다.

## 선택과 이유

- 모델에는 service/minutes/errors_only/unresolved를 제안하는 propose_log_query 도구만 제공한다. 이 도구는 시스템에 접근하지 않는다.
- 코드는 필드 집합·허용 서비스·정수 1~60분·참/거짓·미해결 조건을 검증한다. 누락을 기본값으로 채우거나 범위를 몰래 줄이지 않는다.
- 오류 필터는 기존 JSON level=error 조건이다. 지연·금액 이상을 이 조건으로 자동 환원하지 않는다.
- 자연어 입력 기본값은 조건 미리보기다. --run-query를 명시하면 이번 요청에서 생성한 조건을 검증·표시한 뒤 실행한다. 이전 미리보기를 저장하고 승인·재개하는 기능은 아니다. 다시 실행하면 모델 제안과 상대 시각이 달라질 수 있다.
- 자연어와 CLI 대상·시간·필터 옵션을 섞지 않는다. 반환 상한·HTTP 제한은 사용자가 CLI로 정하며 모델은 변경할 수 없다.
- 현재 입구는 단일 서비스·최근 1~60분·일반/오류 로그만 지원한다. 고정 시각·요청 ID·복수 대상·변경 작업은 미해결 조건으로 돌려보내도록 모델에 지시한다. 자유 문장의 조건이 누락됐는지를 코드가 완전히 검증하지는 못한다.
- LangGraph: interpret → validate → execute 또는 종료. execute는 기존 QUERY_TIMEOUT 2회 상한을 적용하고 report에서 기존 코드 사실·모델 설명을 재사용한다. chain도 같은 정책을 적용한다.

| 새 조건 | 최소 관측 | 불일치 시 수정할 위치 |
|---|---|---|
| 명확한 요청 미리보기 | 모델 제안 1회, 코드 조건 표시, Loki 호출 0회 | validate 실행 분기 |
| 대상·시간·증상 누락 | 세 종류 질문, --run-query여도 조회 0회 | 필수 조건 검사 |
| 범위 초과·없는 서비스·미해결 조건 | 축소/임의 보정 없이 조회 0회 | 허용 범위 검사 |
| 명확한 요청 실행 | 같은 대상·필터·고정된 시간으로 조회, 설명까지 모델 2회 | 조건 전달 |
| 조회 시간 초과 후 성공 | 동일 조건으로 도구 2회, 재해석 없음 | 재시도 분기 |
| 잘못된 제안 형식 | 원래 제안 표시·오류 안내·조회 없음·종료 코드 2 | 모델 계약 검사 |

## 실제 관측

별도 Linux Python 3.12.14 환경에서 실제 ChatOllama SDK·LangGraph를 사용하고 모델 HTTP 및 query_logs 결과를 대역으로 제공했다. 실제 Qwen/Gemini/Loki 서버에는 연결하지 않았다.

```bash
python -m unittest discover -s examples/2026-10-07 -p test_natural_request.py -v
python -m unittest discover -s examples/2026-10-07 -p 'test_*workflows.py' -v
```

새 검사 6개, 변경된 CLI 진입점의 기존 회귀 14개 PASS. 초기에 미리보기 출력 테스트가 JSON 인용부호 이스케이프를 고려하지 않아 실패했고, JSON 문자열 대신 표시된 필터 정책을 확인하도록 수정했다. 제품 코드 문제는 아니었다.

이 결과는 실행 통제와 SDK 연결 계약의 근거다. 실제 모델이 문장의 의미를 정확히 해석한다는 근거로 쓰지 않는다. 사용자 PC에서는 다음 두 미리보기로 새 불확실성만 확인한다.

1. 'order-api의 최근 10분 오류 로그를 확인해줘' → service=order-api, minutes=10, errors_only=true, unresolved=[]이면 해당 사례의 해석 확인 종료.
2. '아까 결제가 이상했어' → 대상·시간·증상 질문과 Loki 조회 없음이면 해당 사례 확인 종료. 임의 보정하면 추출 지시/모델 선택을 검토한다.

코드는 모델이 사용자의 의도를 잘못 해석해도 허용 범위 안에 있으면 통과시킬 수 있다. 이번 기본 미리보기는 그 차이를 사람이 확인하기 위한 것이다. 실제 조회는 조건을 검토한 뒤 별도 실행할 수 있으며, 최신 범위의 빈 결과도 유효한 조회 결과다. 빈 결과를 서비스 정상으로 해석하지 않는다.
